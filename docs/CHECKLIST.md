# 개발 체크리스트 · Cosmodoro

[PLAN.md](PLAN.md)의 0~5단계(배포까지)를 진행하면서 체크해요. 기준 디자인은 `design/drafts/v6-main.html`, `v6-flight.html`이에요.
`[x]` 끝남 · `[ ]` 아직 · `[-]` 미뤄 둠(이유 적음)

## 정한 것 (가장 단순하게)

PLAN.md보다 도구를 줄였어요. 필요해지면 그때 더해요.

| PLAN.md | 실제 | 이유 |
|---|---|---|
| Vite | 없음. 초안 HTML을 그대로 서버가 내보내요 | 초안이 빌드 없이 돌아가요 |
| PostgreSQL + PGlite + Drizzle | 배포: Neon(Postgres), 로컬: Node 내장 `node:sqlite` 파일. ORM 없이 같은 SQL | `DATABASE_URL`이 있으면 Postgres, 없으면 SQLite |
| 테이블별 동기화 | 사용자마다 JSON 문서 하나(`user_data`) | 데이터가 작아요. 비행 기록은 합치고, 나머지는 나중에 올린 쪽이 이겨요 |
| IndexedDB | localStorage 그대로 | 초안 코드가 전부 localStorage라서요 |
| packages/shared | 없음 | 같이 쓸 코드가 아직 없어요 |

- **화면:** 초안을 그대로 옮겼어요(`apps/web/index.html` = 메인, `flight.html` = 비행·태양계).
- **같은 주소:** 서버가 웹 페이지도 같이 내보내서 로그인 쿠키가 다른 도메인으로 넘어가지 않아요.
- **예시 데이터 삭제:** 처음 쓰는 사람에게 남의 할 일과 가짜 통계가 보이지 않아요.

## 0단계 · 초안을 웹 앱으로 옮기기

- [x] `apps/web/`에 v6 메인·비행, `cosmo-shared.js`, 행성 지도·별 목록(`assets/`), 로고(`brand/`)
- [x] 페이지 사이 링크를 새 주소로(`v6-main.html` → `./`, `v6-flight.html` → `flight.html`)
- [x] **보안:** 사용자가 쓴 글(카테고리 이름, 미션 제목)이 HTML로 실행되지 않게(XSS). 브라우저에서 `<img onerror>`를 넣어 확인
- [x] 메인, 비행, 태양계가 콘솔 오류 없이 뜨는지 확인

## 1단계 · 진짜 통계

- [x] 예시 할 일 목록 삭제(메인, 비행). 미션 없이 비행하면 "자유 비행"
- [x] 비행은 도착했을 때만 기록돼요(예전엔 비행 중 미션을 체크하면 미완료 비행도 저장됐어요)
- [x] 비행 기록 200개 제한 삭제
- [x] 통계를 실제 기록으로: 오늘 집중·목표 %·비행 횟수, 요일·주·월 그래프, 주제별, 별자리 스트릭, 이번 주 합계
- [x] 확인: 1분 비행을 끝까지 날리고 메인 통계가 0시간 51분으로 바뀜
- [x] 태양계 확대 화면 "집중한 시간"은 원래부터 `cosmodoro.flights`를 더해요

## 2단계 · 서버, DB, 로그인

- [x] `server/src/app.js`: Hono + Better Auth + `node:sqlite`
- [x] 시작할 때 로그인 테이블을 자동으로 만들어요(Better Auth 마이그레이션)
- [x] 이메일·비밀번호 가입과 로그인(8자 이상), 세션 쿠키(httpOnly, https에선 Secure)
- [x] **보안:** 로그인 시도 횟수 제한(Better Auth), 운영 환경에서 `BETTER_AUTH_SECRET`이 없으면 서버가 안 떠요
- [-] 구글 로그인: 코드는 있어요. 구글 클라우드에서 OAuth 클라이언트를 만들어 `GOOGLE_CLIENT_ID/SECRET`을 넣으면 버튼이 나타나요(사용자 계정 필요)
- [-] 이메일 인증·비밀번호 찾기: 메일 보내는 서비스(예: Resend) 계정이 필요해요

## 3단계 · 동기화와 진짜 로그인 화면

- [x] 메인의 가짜 로그인을 진짜로(가입, 로그인, 로그아웃, 오류 문구)
- [x] `apps/web/sync.js`: 페이지가 열릴 때 먼저 동기화(최대 2.5초 기다림), 그 뒤 20초마다와 페이지를 떠날 때 바뀐 것만 올려요
- [x] 로그인 전 기록은 첫 로그인 때 계정으로 합쳐요(할 일은 더하고, 비행은 모두 남겨요)
- [x] 로그아웃하면 이 기기의 계정 데이터를 지워요
- [x] 인터넷이 끊기면 이 기기 데이터로 그대로 열리고, 다음에 연결되면 올라가요
- [x] **보안:** 서버는 세션의 `user_id` 행만 읽고 써요. 테스트: 로그인 없이 401, 위조 쿠키 401, B가 A의 데이터를 못 봄
- [x] 확인: 브라우저 저장소를 지우고(새 기기 흉내) 다시 열면 할 일·비행 기록이 돌아옴
- [-] 두 기기에서 동시에 오프라인으로 할 일을 고치면 나중에 올린 쪽만 남아요. 실제로 문제가 되면 항목별 시간 기록을 붙여요

## 4단계 · 캘린더

- [x] 마감일 있는 할 일을 iCal(.ics) 구독 주소로(`/api/ical/<토큰>.ics`)
- [x] **보안:** 주소는 추측할 수 없는 긴 토큰(192비트), "새 주소"를 누르면 예전 주소는 404
- [x] 계정 패널에 "주소 복사"와 "새 주소"(복사가 막히면 주소를 그대로 보여 줘요)
- [-] 비행 도착 알림: 비행 화면이 열려 있으면 도착 화면과 소리가 이미 알려 줘요. 탭을 숨긴 채 쓰는 사람이 많으면 붙여요
- [-] 시간을 정한 비행 일정과 그 시각 알림: 새 화면이 필요해서 시안부터 보여 드려요

## 5단계 · 배포 (Vercel + Neon, 2026-11-02)

**주소: https://cosmodoro-five.vercel.app**

- [x] 호스팅: Railway는 신규 가입이 막혀 있어서 Vercel(Hobby, 비상업용 무료) + Neon(무료 Postgres)으로
- [x] `api/index.js`(모든 `/api` 요청), `vercel.json`(웹은 `apps/web`을 그대로, 함수 지역 `sin1` = DB와 같은 싱가포르)
- [x] GitHub 연결: main에 푸시하면 자동 배포
- [x] 환경 변수: `BETTER_AUTH_SECRET`(Secret), `IP_HEADER=x-real-ip`, Neon이 넣은 `DATABASE_URL`. 공개 주소는 Vercel의 `VERCEL_PROJECT_PRODUCTION_URL`을 써요(도메인을 바꿔도 따라가요)
- [x] 로그인 시도 제한을 DB에 저장(서버 함수끼리 메모리를 공유하지 않아서). 실제 주소에서 3번 틀리면 429 확인
- [x] 실제 주소 확인: 메인·비행 페이지·행성 지도 200, 로그인 없이 동기화 401, 다른 사이트 폼 403, 서버 파일 404, 보안 헤더
- [ ] 실제 주소에서 사용자가 직접 가입 → 비행 → 통계 → 다른 기기 동기화 확인
- [-] DB 백업: Neon 무료 요금제의 기본 복구 기간에 맡겨요. 중요한 데이터가 쌓이면 정기 백업을 붙여요
- [-] 상업용으로 쓰게 되면 Vercel Pro로 올려야 해요(Hobby는 비상업용)
